# Reel Dinner app build (iPhone and Android)

The app is the website wrapped in Capacitor 8. The same index.html, app.js and menu files run in both. One switch decides how they behave: `window.REEL_APP`.

## App mode

app-mode.js loads first, in the head of index.html. It sets:

- `REEL_APP`: true inside the app, in the www/ build, and in a browser opened with `?app=1` (it sticks for the tab; `?app=0` turns it off). False on the website.
- `REEL_NATIVE`: true only inside the real app (Capacitor reports a native platform).
- `window.REEL`: helpers app.js calls for the share sheet, Save to Files, the print dialog, haptics, movie night reminders and posts to other sites. On the website each helper says "not handled" and the old browser code runs. Any use of REEL in app.js outside a `REEL_NATIVE` or `REEL_APP` branch checks `typeof REEL!=="undefined"` first, so the site still works if app-mode.js fails to load.

On the website app-mode.js stops after setting up REEL. Nothing else changes.

In app mode (docs/ARTWORK-RIGHTS.md, option E):

- No film artwork. TMDB posters, stills and logos, the 124 generated posters, the film frame and the menu photos listed in app-art.js are swapped before the page asks for them. Each slot gets an original panel drawn in the menu's own type and colours. No request goes to image.tmdb.org.
- A content security policy (`img-src 'self' data: blob:`) stops any outside image as a backstop.
- The Galaxy Video photos that show poster lookalikes are swapped for app copies (scripts/app-hero.py): the shopfront (flyers over the window posters), the aisles (shelves out of focus) and the late show curtain (shelves either side out of focus). The raw shopfront photo (assets/hero/shopfront*.webp) is never copied into the app.
- The privacy and support links and the film request form go to https://reeldinner.com. The request form and the member card sync are sent through Capacitor's native HTTP, because those servers only allow reeldinner.com as a browser origin.
- The service worker is not registered. The app carries every file, and Android serves the app from https://localhost, where a worker would cache a second copy for nothing.
- Save PDF and Save image go out through the share sheet (Save to Files on iPhone). Print opens the phone's print dialog. The calendar button sets phone reminders (start cooking, showtime) and shares the .ics file.

Test app mode in a browser with `https://reeldinner.com/?app=1`, or locally with `python3 -m http.server` and `?app=1`. The native helpers fall back to the browser there.

## Files

| File | What it is |
|---|---|
| app-mode.js | The switch, the artwork swap and window.REEL |
| app-art.js | Generated by scripts/app-art.cjs: the blocked pictures, the shop photo swaps and any per-film poster art. Do not edit by hand |
| scripts/app-art.cjs | Builds app-art.js from docs/image-credits.md and the assets folders |
| scripts/app-hero.py | Makes the app copies of the Galaxy Video photos in assets/app/ (needs Pillow) |
| scripts/app-icons.py | Makes the app icons and splash screens |
| scripts/build-app.cjs | Builds www/, the folder that goes in the app. Fails if any studio artwork ends up in it |
| capacitor.config.json | App id com.reeldinner.app, name, colours, notification icon |
| android/, ios/ | The native projects (Capacitor) |
| package.json | Capacitor and its plugins (share, filesystem, haptics, local notifications, printer) |

www/ and node_modules/ are not in git.

## Build

From the repo root:

1. `npm install`
2. `node scripts/build-data.cjs` (stamps, as for the website)
3. `npm run build:app` (runs app-art.cjs, then builds www/)
4. `npx cap sync` (copies www/ and the plugins into android/ and ios/)

After adding a Galaxy Video photo with posters in it, add it to app-hero.py and the swap list in app-art.cjs, then rerun both. After adding a menu photo, give it a line in docs/image-credits.md or app-art.cjs blocks it.

### Android

Works on Linux. Needs a JDK (21) and the Android SDK.

- Debug build: `cd android && ./gradlew assembleDebug`. The APK lands in android/app/build/outputs/apk/debug/.
- Permissions in AndroidManifest.xml: INTERNET, POST_NOTIFICATIONS (the Android 13+ prompt for reminders) and SCHEDULE_EXACT_ALARM (reminders on the minute).
- Store: Google Play Console account (US$25 one-off), then a signed release bundle (`./gradlew bundleRelease` with an upload key).

### iPhone

Needs a Mac with Xcode. There is no Mac here, so this needs a cloud Mac (or a CI service with Mac runners).

- `npx cap open ios`, set the team and signing in Xcode, then build to a device or archive for TestFlight.
- Apple Developer Program (US$99 a year). Josh is holding off paying until the first test build is ready.
